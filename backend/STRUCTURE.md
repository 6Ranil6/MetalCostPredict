# Структура проекта Backend

## Архитектура после декомпозиции

Backend приложение разделено на логические модули для лучшей организации кода и переиспользования.

### Основные файлы

#### `app.py` - Точка входа приложения
- Главный файл, создающий и конфигурирует приложение aiohttp
- Импортирует все обработчики маршрутов из папки `handlers/`
- Инициализирует БД и загружает ML модель при старте
- Настраивает CORS для всех маршрутов

#### `config.py` - Конфигурация и константы
- `IMPORTANT_FEATURES` - список важных признаков для модели
- `NUMERIC_FEATURES` - числовые признаки
- `CAT_FEATURES` - категориальные признаки
- `BASE_DIR` - базовая директория проекта
- `MAX_FILE_SIZE` - максимальный размер загружаемого файла (5МБ)

#### `model.py` - Работа с ML моделью
- `load_local_model()` - загружает CatBoost модель с диска
- `get_model_predict()` - получает предсказания от модели для DataFrame

#### `data_validation.py` - Валидация и обработка данных
- `check_data_format()` - проверяет и приводит данные к нужному формату
- `clean_input_data_for_json()` - преобразует значения в JSON-совместимый формат

### Папка `handlers/` - Обработчики HTTP маршрутов

Каждый файл содержит группу логически связанных обработчиков.

#### `handlers/__init__.py`
- Централизованный импорт всех маршрутов
- Экспортирует `*_routes` из каждого модуля

#### `handlers/health.py` - Проверка статуса
- **GET** `/health` - Проверка работоспособности сервера

#### `handlers/auth.py` - Аутентификация
- **POST** `/api/register` - Регистрация нового пользователя
- **POST** `/api/login` - Вход пользователя (устанавливает cookie)
- **POST** `/api/logout` - Выход пользователя (удаляет cookie)

#### `handlers/feedback.py` - Обратная связь
- **POST** `/api/feedback` - Сохранение сообщения обратной связи

#### `handlers/predictions.py` - Предсказания цен
- **POST** `/predict-manual` - Предсказание по ручному вводу данных
- **POST** `/predict-file` - Предсказание по загруженному файлу (CSV/Parquet)

#### `handlers/history.py` - История предсказаний
- **GET** `/api/predictions-history/{user_id}` - Получить историю предсказаний
- **POST** `/api/hide-prediction/{prediction_id}/{user_id}` - Скрыть одно предсказание
- **POST** `/api/hide-all-predictions/{user_id}` - Скрыть все предсказания

## Зависимости между модулями

```
app.py (точка входа)
├── config.py (константы)
├── model.py 
│   ├── config.py
│   └── CatBoost
├── app_db.py (существующий файл)
└── handlers/
    ├── health.py
    ├── auth.py (app_db)
    ├── feedback.py (app_db)
    ├── predictions.py
    │   ├── config.py
    │   ├── model.py
    │   ├── data_validation.py
    │   └── app_db.py
    └── history.py (app_db)
```

## Преимущества структуры

1. **Модульность** - каждый файл отвечает за одну область функциональности
2. **Масштабируемость** - легко добавлять новые обработчики в папку `handlers/`
3. **Переиспользование** - модули `config`, `model`, `data_validation` используются в нескольких обработчиках
4. **Тестируемость** - каждый модуль можно тестировать отдельно
5. **Читаемость** - логическая организация улучшает понимание кода
6. **Поддержка** - легче находить и исправлять баги

## Как расширять проект

### Добавить новый обработчик
1. Создать файл `handlers/new_feature.py`
2. Определить `new_feature_routes = web.RouteTableDef()`
3. Добавить обработчики функции
4. Импортировать в `handlers/__init__.py`
5. Добавить `app.add_routes(new_feature_routes)` в `app.py`

### Добавить новую конфигурацию
- Просто добавить новую переменную в `config.py`
- Импортировать где нужна: `from config import NEW_VAR`

## Импорты в обработчиках

Все обработчики следуют единообразному стилю:

```python
from aiohttp import web
from app_db import ...  # если нужна БД
from config import ...  # если нужны константы
from model import ...   # если нужно предсказание
from data_validation import ...  # если нужна валидация
```

## Производительность и безопасность

- **Ограничение размера запроса**: 10МБ на весь запрос
- **Ограничение размера файла**: 5МБ для загружаемых файлов
- **CORS**: разрешены запросы со всех источников с поддержкой cookies
- **Валидация данных**: все входные данные проверяются перед обработкой
- **HttpOnly cookies**: использование secure cookies для защиты от XSS
